Same data, six engines

Each engine builds the same seeded dataset of sales rows, then filters, groups, joins, searches, sorts and summarises it. Results are checked against each other, so you can see who is fastest and that they all got the same answer.

How it works

Every row has a category (20), a region (5), a value between 0 and 1000, a quantity from 1 to 10, a customer, and a product code such as SKU-0042. A separate table gives each of 100,000 customers a discount tier. Everything comes from the mulberry32 generator, implemented identically in each language, so every engine sees the exact same data.

Rust
Release build, columnar Vecs, spread across cores with rayon.
JavaScript
Typed arrays in shared memory, one worker thread per core, on Node.js and in your own browser.
Python + pandas
Vectorised NumPy generation and pandas DataFrame operations. Runs on one core, because pandas has no built-in way to use more.
Python + Polars
Everything in Polars, including generating the data with its own expression engine on Arrow memory. Polars spreads work across cores by itself.
Python (pure)
Plain loops, no libraries. One process per core, because the GIL stops threads from running Python in parallel.

Multi-core runs include the cost of splitting the work and combining results, such as merging sorted chunks. Timings exclude network transfer. Browser results depend on your device.
